¿Qué es la
Minería de Datos?

La Minería de Datos (Data Mining) es el proceso de descubrir patrones, correlaciones, anomalías y tendencias significativas en grandes conjuntos de datos, combinando métodos estadísticos, aprendizaje automático y bases de datos.

A través de consultas analíticas avanzadas sobre AdventureWorks2022, exploraremos cómo extraer inteligencia de negocio real: segmentación de clientes, análisis de rentabilidad, detección de anomalías y modelos predictivos.

Cada ejemplo incluye el script T-SQL completo, una explicación del objetivo y las tablas involucradas de la base de datos de ejemplo de Microsoft SQL Server.

Análisis de Ventas · Agregación

Ranking de productos más vendidos por categoría y año

🎯 Objetivo
Identificar cuáles son los productos con mayor volumen de ventas en cada categoría y año fiscal. Este análisis permite al equipo comercial priorizar inventario, diseñar campañas dirigidas y detectar qué líneas de producto generan mayor demanda. Usa funciones de ventana RANK() para obtener una clasificación relativa dentro de cada categoría.

Se usan las tablas Sales.SalesOrderDetail, Sales.SalesOrderHeader, Production.Product y Production.ProductSubcategory / ProductCategory. La función RANK() OVER (PARTITION BY ...) clasifica los productos dentro de cada categoría según la cantidad total vendida, permitiendo extraer sólo el TOP N por grupo.

SalesOrderDetail Product ProductCategory Window Functions

T-SQL 
-- ============================================================
-- EJEMPLO 1: Ranking de productos más vendidos por categoría
-- Base: AdventureWorks2022
-- ============================================================

WITH VentasPorProducto AS (
    SELECT
        pc.Name                              AS Categoria,
        p.Name                               AS Producto,
        YEAR(soh.OrderDate)                  AS Anio,
        SUM(sod.OrderQty)                    AS TotalUnidades,
        SUM(sod.LineTotal)                   AS TotalIngresos
    FROM Sales.SalesOrderDetail    sod
    JOIN Sales.SalesOrderHeader    soh  ON sod.SalesOrderID  = soh.SalesOrderID
    JOIN Production.Product         p    ON sod.ProductID     = p.ProductID
    JOIN Production.ProductSubcategory ps ON p.ProductSubcategoryID = ps.ProductSubcategoryID
    JOIN Production.ProductCategory  pc   ON ps.ProductCategoryID = pc.ProductCategoryID
    GROUP BY pc.Name, p.Name, YEAR(soh.OrderDate)
),
Ranking AS (
    SELECT
        Categoria, Producto, Anio,
        TotalUnidades, TotalIngresos,
        RANK() OVER (
            PARTITION BY Categoria, Anio
            ORDER BY TotalUnidades DESC
        ) AS Posicion
    FROM VentasPorProducto
)
SELECT
    Anio,
    Categoria,
    Posicion,
    Producto,
    TotalUnidades,
    FORMAT(TotalIngresos, 'C', 'en-US') AS Ingresos
FROM Ranking
WHERE Posicion <= 5   -- Top 5 por categoría y año
ORDER BY Anio, Categoria, Posicion;

Segmentación · Comportamiento de Compra

Segmentación de clientes por frecuencia y valor de compra

🎯 Objetivo
Clasificar a los clientes en segmentos (Alto, Medio, Bajo) según la frecuencia de sus pedidos y el gasto total acumulado. Esta técnica de segmentación permite al área de marketing personalizar ofertas, identificar clientes VIP y diseñar programas de fidelización basados en datos reales de comportamiento.

Se emplean Sales.Customer, Sales.SalesOrderHeader y Person.Person. Con NTILE(3) se divide la distribución de clientes en tres tercios según gasto y frecuencia, generando una segmentación automática sin necesidad de umbrales manuales.

Customer SalesOrderHeader NTILE Segmentación

T-SQL 
-- ============================================================
-- EJEMPLO 2: Segmentación de clientes por frecuencia y valor
-- ============================================================

WITH MetricasCliente AS (
    SELECT
        c.CustomerID,
        ISNULL(p.FirstName + ' ' + p.LastName, 'Cliente Empresa') AS NombreCliente,
        COUNT(soh.SalesOrderID)   AS TotalPedidos,
        SUM(soh.TotalDue)         AS GastoTotal,
        AVG(soh.TotalDue)         AS TicketPromedio,
        MIN(soh.OrderDate)        AS PrimerPedido,
        MAX(soh.OrderDate)        AS UltimoPedido
    FROM Sales.Customer       c
    JOIN Sales.SalesOrderHeader soh ON c.CustomerID = soh.CustomerID
    LEFT JOIN Person.Person    p   ON c.PersonID   = p.BusinessEntityID
    GROUP BY c.CustomerID, p.FirstName, p.LastName
),
Segmentado AS (
    SELECT
        CustomerID, NombreCliente,
        TotalPedidos, GastoTotal, TicketPromedio,
        PrimerPedido, UltimoPedido,
        NTILE(3) OVER (ORDER BY GastoTotal  DESC) AS TercilGasto,
        NTILE(3) OVER (ORDER BY TotalPedidos DESC) AS TercilFrecuencia
    FROM MetricasCliente
)
SELECT
    CustomerID,
    NombreCliente,
    TotalPedidos,
    FORMAT(GastoTotal,    'C', 'en-US') AS GastoTotal,
    FORMAT(TicketPromedio,'C', 'en-US') AS TicketPromedio,
    CASE
        WHEN TercilGasto = 1 AND TercilFrecuencia = 1 THEN '⭐ VIP - Alto Valor'
        WHEN TercilGasto = 1                           THEN '💎 Alto Valor'
        WHEN TercilFrecuencia = 1                      THEN '🔄 Alta Frecuencia'
        WHEN TercilGasto = 2 OR  TercilFrecuencia = 2  THEN '📊 Valor Medio'
        ELSE '📉 Bajo Valor'
    END AS Segmento,
    PrimerPedido, UltimoPedido
FROM Segmentado
ORDER BY GastoTotal DESC;

Análisis de Cesta · Market Basket

Productos comprados frecuentemente juntos (Market Basket)

🎯 Objetivo
Descubrir pares de productos que los clientes tienden a adquirir en el mismo pedido. Este análisis de asociación es la base del sistema de recomendación "los clientes también compraron…". Permite optimizar la distribución física en tiendas, los bundles de productos y las campañas de venta cruzada (cross-selling).

Técnica clásica de Market Basket Analysis. Se hace un auto-join de Sales.SalesOrderDetail sobre sí misma para encontrar pares de productos distintos dentro del mismo SalesOrderID. Se calcula el soporte (frecuencia absoluta de co-ocurrencia) y se filtra por el umbral mínimo de apariciones.

SalesOrderDetail Self-Join Association Rules Cross-Sell

T-SQL 
-- ============================================================
-- EJEMPLO 3: Market Basket Analysis (pares de productos)
-- ============================================================

WITH ParesProducto AS (
    SELECT
        a.SalesOrderID,
        p1.Name     AS ProductoA,
        p2.Name     AS ProductoB
    FROM       Sales.SalesOrderDetail a
    JOIN       Sales.SalesOrderDetail b
        ON  a.SalesOrderID = b.SalesOrderID
        AND a.ProductID    < b.ProductID   -- evitar duplicados y autopares
    JOIN Production.Product p1 ON a.ProductID = p1.ProductID
    JOIN Production.Product p2 ON b.ProductID = p2.ProductID
),
Frecuencia AS (
    SELECT
        ProductoA,
        ProductoB,
        COUNT(*) AS VecesJuntos
    FROM ParesProducto
    GROUP BY ProductoA, ProductoB
),
TotalOrdenes AS (
    SELECT COUNT(DISTINCT SalesOrderID) AS Total
    FROM Sales.SalesOrderHeader
)
SELECT
    f.ProductoA,
    f.ProductoB,
    f.VecesJuntos,
    CAST(f.VecesJuntos * 100.0 / t.Total AS DECIMAL(5,2)) AS SoportePct
FROM Frecuencia f
CROSS JOIN TotalOrdenes t
WHERE f.VecesJuntos >= 50   -- soporte mínimo de 50 co-ocurrencias
ORDER BY f.VecesJuntos DESC
OFFSET 0 ROWS FETCH NEXT 30 ROWS ONLY;

Modelo RFM · Análisis de Valor de Cliente

Modelo RFM: Recencia, Frecuencia y Valor Monetario

🎯 Objetivo
Aplicar el modelo RFM (Recency, Frequency, Monetary) para calificar a cada cliente en tres dimensiones clave: cuándo compró por última vez, con qué frecuencia compra y cuánto dinero gasta. La combinación de estas tres puntuaciones produce un perfil integral del valor de cada cliente y permite priorizar acciones de retención y reactivación.

El modelo RFM es un estándar en CRM y marketing analítico. Se calcula la Recencia como días transcurridos desde el último pedido, la Frecuencia como número total de órdenes y el Valor Monetario como suma de ingresos. Luego NTILE(5) puntúa cada dimensión del 1 al 5, y la suma de los tres puntajes da una calificación global del cliente.

RFM Customer Lifetime Value NTILE(5) CRM

T-SQL 
-- ============================================================
-- EJEMPLO 4: Modelo RFM completo
-- ============================================================

DECLARE @FechaRef DATE = (SELECT MAX(OrderDate) FROM Sales.SalesOrderHeader);

WITH BaseRFM AS (
    SELECT
        c.CustomerID,
        ISNULL(p.FirstName + ' ' + p.LastName, 'Empresa') AS Cliente,
        DATEDIFF(DAY, MAX(soh.OrderDate), @FechaRef) AS Recencia,
        COUNT(soh.SalesOrderID)                         AS Frecuencia,
        SUM(soh.TotalDue)                               AS Monetario
    FROM Sales.Customer        c
    JOIN Sales.SalesOrderHeader soh ON c.CustomerID = soh.CustomerID
    LEFT JOIN Person.Person    p   ON c.PersonID   = p.BusinessEntityID
    GROUP BY c.CustomerID, p.FirstName, p.LastName
),
Puntajes AS (
    SELECT
        CustomerID, Cliente, Recencia, Frecuencia, Monetario,
        -- Recencia: menor días = mejor puntaje (invertido)
        6 - NTILE(5) OVER (ORDER BY Recencia  DESC) AS R_Score,
        NTILE(5) OVER (ORDER BY Frecuencia ASC)  AS F_Score,
        NTILE(5) OVER (ORDER BY Monetario  ASC)  AS M_Score
    FROM BaseRFM
)
SELECT
    CustomerID,
    Cliente,
    Recencia    AS Dias_UltimaCompra,
    Frecuencia  AS Num_Pedidos,
    FORMAT(Monetario, 'C', 'en-US') AS Gasto_Total,
    R_Score, F_Score, M_Score,
    R_Score + F_Score + M_Score       AS RFM_Total,
    CASE
        WHEN R_Score + F_Score + M_Score >= 13 THEN '🏆 Champions'
        WHEN R_Score + F_Score + M_Score >= 10 THEN '💰 Loyal Customers'
        WHEN R_Score >= 4                       THEN '🆕 Recent Customers'
        WHEN F_Score >= 4                       THEN '🔄 Frequent Buyers'
        WHEN R_Score <= 2                       THEN '😴 At Risk'
        ELSE                                          '📊 Occasional'
    END AS Segmento_RFM
FROM Puntajes
ORDER BY RFM_Total DESC;

Series Temporales · Tendencias

Análisis de tendencias mensuales con media móvil

🎯 Objetivo
Visualizar la evolución de ventas mes a mes e identificar tendencias de crecimiento o caída utilizando medias móviles de 3 meses. Este análisis temporal permite detectar estacionalidades, picos de demanda y períodos de contracción para planificar producción, inventario y presupuesto con mayor precisión.

Las funciones de ventana AVG() OVER (ORDER BY ... ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) calculan la media móvil sin necesidad de subconsultas complejas. También se calcula el crecimiento porcentual mes a mes usando LAG() para comparar con el período anterior.

SalesOrderHeader Moving Average LAG() Time Series

T-SQL 
-- ============================================================
-- EJEMPLO 5: Tendencias mensuales con media móvil de 3 meses
-- ============================================================

WITH VentasMensuales AS (
    SELECT
        YEAR(OrderDate)                AS Anio,
        MONTH(OrderDate)               AS Mes,
        FORMAT(OrderDate, 'yyyy-MM')   AS Periodo,
        COUNT(SalesOrderID)            AS NumOrdenes,
        SUM(TotalDue)                  AS VentasBrutas,
        SUM(SubTotal)                  AS SubTotal,
        SUM(Freight)                   AS CostoEnvio
    FROM Sales.SalesOrderHeader
    WHERE Status = 5   -- solo órdenes aprobadas
    GROUP BY YEAR(OrderDate), MONTH(OrderDate), FORMAT(OrderDate, 'yyyy-MM')
),
ConMediaMovil AS (
    SELECT
        Periodo, Anio, Mes,
        NumOrdenes, VentasBrutas, SubTotal, CostoEnvio,
        AVG(VentasBrutas) OVER (
            ORDER BY Anio, Mes
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ) AS MediaMovil3M,
        LAG(VentasBrutas, 1) OVER (ORDER BY Anio, Mes) AS MesAnterior
    FROM VentasMensuales
)
SELECT
    Periodo,
    NumOrdenes,
    FORMAT(VentasBrutas, 'C0', 'en-US')  AS VentasBrutas,
    FORMAT(MediaMovil3M, 'C0', 'en-US')  AS MediaMovil_3M,
    CASE
        WHEN MesAnterior IS NULL         THEN 'N/A'
        WHEN MesAnterior = 0             THEN '∞'
        ELSE FORMAT(
                (VentasBrutas - MesAnterior) * 100.0 / MesAnterior,
                'N2'
             ) + '%'
    END     AS CrecimientoMoM,
    CASE
        WHEN VentasBrutas > MediaMovil3M THEN '📈 Por encima de media'
        WHEN VentasBrutas < MediaMovil3M THEN '📉 Por debajo de media'
        ELSE                                   '➡️ En línea con media'
    END     AS Tendencia
FROM ConMediaMovil
ORDER BY Anio, Mes;

Análisis ABC · Rentabilidad

Clasificación ABC de productos por margen de rentabilidad

🎯 Objetivo
Aplicar el análisis de Pareto (regla 80/20) para clasificar los productos en categorías A, B y C según su contribución al margen total. Los productos A generan el 80% del margen con el 20% del catálogo. Esta clasificación orienta decisiones de producción, descuentos, discontinuación de productos y gestión de inventario.

Se calcula el margen unitario como la diferencia entre el precio de lista y el costo estándar. Luego SUM() OVER (ORDER BY ... ROWS UNBOUNDED PRECEDING) acumula el porcentaje progresivo, clasificando como A los primeros productos que alcanzan el 80% del margen acumulado, B hasta el 95%, y el resto como C.

Product SalesOrderDetail Pareto ABC Running Total

T-SQL 
-- ============================================================
-- EJEMPLO 6: Análisis ABC de rentabilidad de productos
-- ============================================================

WITH MargenProducto AS (
    SELECT
        p.ProductID,
        p.Name                                         AS Producto,
        p.ListPrice,
        p.StandardCost,
        p.ListPrice - p.StandardCost                  AS MargenUnitario,
        SUM(sod.OrderQty)                              AS UnidadesVendidas,
        SUM(sod.OrderQty * (p.ListPrice - p.StandardCost)) AS MargenTotal
    FROM Production.Product      p
    JOIN Sales.SalesOrderDetail  sod ON p.ProductID = sod.ProductID
    WHERE p.StandardCost > 0
      AND p.ListPrice     > p.StandardCost
    GROUP BY p.ProductID, p.Name, p.ListPrice, p.StandardCost
),
Acumulado AS (
    SELECT
        ProductID, Producto, ListPrice, StandardCost,
        MargenUnitario, UnidadesVendidas, MargenTotal,
        SUM(MargenTotal) OVER ()                       AS MargenGlobal,
        SUM(MargenTotal) OVER (
            ORDER BY MargenTotal DESC
            ROWS UNBOUNDED PRECEDING
        ) AS MargenAcumulado
    FROM MargenProducto
)
SELECT
    ProductID,
    Producto,
    FORMAT(ListPrice,     'C', 'en-US') AS PrecioLista,
    FORMAT(StandardCost, 'C', 'en-US') AS Costo,
    FORMAT(MargenUnitario,'C', 'en-US') AS MargenUnitario,
    UnidadesVendidas,
    FORMAT(MargenTotal,   'C0','en-US') AS MargenTotal,
    FORMAT(MargenAcumulado * 100.0 / MargenGlobal, 'N1') + '%' AS PctAcumulado,
    CASE
        WHEN MargenAcumulado <= MargenGlobal * 0.80 THEN '🅐  A - Crítico'
        WHEN MargenAcumulado <= MargenGlobal * 0.95 THEN '🅑  B - Importante'
        ELSE                                           '🅒  C - Marginal'
    END AS ClasificacionABC
FROM Acumulado
ORDER BY MargenTotal DESC;

RRHH · Análisis de Desempeño

Análisis de rendimiento de vendedores con cuota vs real

🎯 Objetivo
Evaluar el desempeño de cada vendedor comparando las ventas reales contra la cuota asignada, calculando el porcentaje de cumplimiento y clasificando su rendimiento. Este análisis es clave para decisiones de compensación, bonificaciones, capacitación y planificación de la fuerza de ventas.

Se cruzan Sales.SalesPerson, Sales.SalesPersonQuotaHistory y Sales.SalesOrderHeader. El porcentaje de cumplimiento revela quiénes superan su cuota (high performers), quiénes están en riesgo y quiénes necesitan apoyo, permitiendo estrategias de coaching diferenciadas.

SalesPerson SalesPersonQuotaHistory Performance KPI

T-SQL 
-- ============================================================
-- EJEMPLO 7: Rendimiento de vendedores (cuota vs real)
-- ============================================================

WITH VentasReales AS (
    SELECT
        soh.SalesPersonID,
        YEAR(soh.OrderDate)    AS Anio,
        MONTH(soh.OrderDate)   AS Mes,
        SUM(soh.SubTotal)      AS VentaReal,
        COUNT(soh.SalesOrderID)AS NumPedidos
    FROM Sales.SalesOrderHeader soh
    WHERE soh.SalesPersonID IS NOT NULL
    GROUP BY soh.SalesPersonID, YEAR(soh.OrderDate), MONTH(soh.OrderDate)
),
Cuotas AS (
    SELECT
        BusinessEntityID AS SalesPersonID,
        YEAR(QuotaDate)  AS Anio,
        MONTH(QuotaDate) AS Mes,
        SalesQuota       AS CuotaAsignada
    FROM Sales.SalesPersonQuotaHistory
)
SELECT
    p.FirstName + ' ' + p.LastName       AS Vendedor,
    e.JobTitle,
    vr.Anio,
    vr.Mes,
    vr.NumPedidos,
    FORMAT(c.CuotaAsignada, 'C0', 'en-US') AS Cuota,
    FORMAT(vr.VentaReal,    'C0', 'en-US') AS VentaReal,
    FORMAT(vr.VentaReal - c.CuotaAsignada, 'C0', 'en-US') AS Diferencia,
    FORMAT(vr.VentaReal * 100.0 / NULLIF(c.CuotaAsignada,0), 'N1') + '%'
        AS PctCumplimiento,
    CASE
        WHEN vr.VentaReal >= c.CuotaAsignada * 1.20 THEN '🌟 Excepcional'
        WHEN vr.VentaReal >= c.CuotaAsignada           THEN '✅ Cumplió cuota'
        WHEN vr.VentaReal >= c.CuotaAsignada * 0.80 THEN '⚠️ En riesgo'
        ELSE                                              '🔴 Bajo cuota'
    END AS Estado
FROM VentasReales      vr
JOIN Cuotas            c   ON vr.SalesPersonID = c.SalesPersonID
                        AND vr.Anio           = c.Anio
                        AND vr.Mes            = c.Mes
JOIN HumanResources.Employee e ON vr.SalesPersonID = e.BusinessEntityID
JOIN Person.Person           p ON vr.SalesPersonID = p.BusinessEntityID
ORDER BY vr.Anio, vr.Mes, vr.VentaReal DESC;

Análisis Geográfico · Geodata

Mapa de calor de ventas por territorio y región geográfica

🎯 Objetivo
Analizar la distribución geográfica de las ventas para identificar los territorios de mayor y menor rendimiento. Este análisis permite reasignar recursos comerciales, abrir nuevas oficinas de ventas, definir estrategias de penetración de mercado regional y optimizar los costos logísticos de envío.

Combina Sales.SalesTerritory, Sales.SalesOrderHeader y datos de dirección (Person.Address, Person.StateProvince, Person.CountryRegion) para construir una vista completa del desempeño por región, incluyendo el ratio ventas/pedido como indicador de ticket promedio territorial.

SalesTerritory Address CountryRegion Geo Analytics

T-SQL 
-- ============================================================
-- EJEMPLO 8: Ventas por territorio geográfico (mapa de calor)
-- ============================================================

WITH VentasTerritorio AS (
    SELECT
        st.TerritoryID,
        st.Name            AS Territorio,
        st.[Group]         AS Region,
        st.CountryRegionCode AS Pais,
        YEAR(soh.OrderDate)AS Anio,
        COUNT(DISTINCT soh.CustomerID)  AS ClientesUnicos,
        COUNT(soh.SalesOrderID)         AS TotalPedidos,
        SUM(soh.TotalDue)               AS VentasBrutas,
        SUM(soh.Freight)                AS CostoLogistico
    FROM Sales.SalesTerritory    st
    JOIN Sales.SalesOrderHeader  soh ON st.TerritoryID = soh.TerritoryID
    WHERE soh.Status = 5
    GROUP BY st.TerritoryID, st.Name, st.[Group], st.CountryRegionCode,
             YEAR(soh.OrderDate)
),
ConRanking AS (
    SELECT
        Territorio, Region, Pais, Anio,
        ClientesUnicos, TotalPedidos, VentasBrutas, CostoLogistico,
        VentasBrutas / NULLIF(TotalPedidos, 0)   AS TicketPromedio,
        VentasBrutas / NULLIF(ClientesUnicos, 0) AS ValorPorCliente,
        RANK() OVER (PARTITION BY Anio ORDER BY VentasBrutas DESC) AS Rank_Ventas,
        SUM(VentasBrutas) OVER (PARTITION BY Anio)                  AS TotalAnual
    FROM VentasTerritorio
)
SELECT
    Anio,
    Rank_Ventas         AS Posicion,
    Territorio,
    Region,
    Pais,
    ClientesUnicos,
    TotalPedidos,
    FORMAT(VentasBrutas,     'C0', 'en-US') AS VentasBrutas,
    FORMAT(TicketPromedio,   'C0', 'en-US') AS TicketPromedio,
    FORMAT(ValorPorCliente,  'C0', 'en-US') AS ValorPorCliente,
    FORMAT(CostoLogistico,   'C0', 'en-US') AS CostoLogistico,
    FORMAT(VentasBrutas * 100.0 / TotalAnual, 'N1') + '%'
        AS ParticipacionMercado,
    CASE
        WHEN Rank_Ventas <= 3  THEN '🔥 Top Tier'
        WHEN Rank_Ventas <= 6  THEN '📊 Mid Tier'
        ELSE                        '🌱 Crecimiento'
    END AS CalorTerritorio
FROM ConRanking
ORDER BY Anio, Rank_Ventas;

Detección de Anomalías · Outliers

Detección de pedidos anómalos mediante desviación estándar

🎯 Objetivo
Identificar órdenes de venta cuyo monto es estadísticamente anormal (outliers) usando la regla de los 2 sigmas (Z-score). Los pedidos que superan o caen muy por debajo del promedio pueden indicar errores de captura, fraudes, descuentos no autorizados o transacciones especiales que requieren revisión manual por el equipo de control interno.

Se calcula la media y la desviación estándar del monto de pedidos usando AVG() y STDEV() con funciones de ventana. Un pedido es anómalo si su Z-score (distancia en sigmas respecto a la media) supera ±2.0, lo que estadísticamente representa menos del 5% de la distribución normal.

SalesOrderHeader Z-Score STDEV() Anomaly Detection

T-SQL 
-- ============================================================
-- EJEMPLO 9: Detección de anomalías con Z-Score estadístico
-- ============================================================

WITH EstadisticaBase AS (
    SELECT
        soh.SalesOrderID,
        soh.OrderDate,
        soh.CustomerID,
        soh.SalesPersonID,
        soh.TerritoryID,
        soh.TotalDue,
        soh.SubTotal,
        soh.TaxAmt,
        soh.Freight,
        -- estadísticas globales por territorio
        AVG(soh.TotalDue)   OVER (PARTITION BY soh.TerritoryID) AS MediaTerritorio,
        STDEV(soh.TotalDue) OVER (PARTITION BY soh.TerritoryID) AS DesvTerritorio,
        -- estadísticas globales
        AVG(soh.TotalDue)   OVER ()                             AS MediaGlobal,
        STDEV(soh.TotalDue) OVER ()                             AS DesvGlobal
    FROM Sales.SalesOrderHeader soh
    WHERE soh.Status = 5
),
ConZScore AS (
    SELECT
        SalesOrderID, OrderDate, CustomerID, SalesPersonID, TerritoryID,
        TotalDue, SubTotal, TaxAmt, Freight,
        MediaTerritorio, DesvTerritorio,
        ABS((TotalDue - MediaTerritorio) / NULLIF(DesvTerritorio, 0)) AS ZScore_Territorio,
        ABS((TotalDue - MediaGlobal)     / NULLIF(DesvGlobal,     0)) AS ZScore_Global
    FROM EstadisticaBase
)
SELECT
    SalesOrderID,
    FORMAT(OrderDate, 'yyyy-MM-dd') AS Fecha,
    CustomerID,
    ISNULL(CAST(SalesPersonID AS VARCHAR), 'Online') AS Vendedor,
    TerritoryID,
    FORMAT(TotalDue,         'C0', 'en-US') AS MontoOrden,
    FORMAT(MediaTerritorio,  'C0', 'en-US') AS MediaTerritorio,
    FORMAT(ZScore_Territorio,'N2')           AS ZScore_Territorio,
    FORMAT(ZScore_Global,    'N2')           AS ZScore_Global,
    CASE
        WHEN ZScore_Global    > 3.0 THEN '🚨 Anomalía Extrema'
        WHEN ZScore_Territorio > 2.5 THEN '⚠️  Sospechoso'
        WHEN ZScore_Global    > 2.0 THEN '🔍 Revisar'
        ELSE                           '✅ Normal'
    END AS NivelAlerta
FROM ConZScore
WHERE ZScore_Global > 2.0   -- mostrar sólo los anómalos
ORDER BY ZScore_Global DESC;

Predicción · Regresión Lineal Simple

Proyección de ventas futuras mediante regresión lineal en SQL

🎯 Objetivo
Construir un modelo de regresión lineal simple directamente en T-SQL para proyectar las ventas de los próximos períodos basándose en la tendencia histórica mensual. Sin necesidad de herramientas externas, este enfoque permite obtener una estimación estadísticamente fundamentada del futuro desempeño de ventas.

La regresión lineal calcula los coeficientes β₀ (intercepto) y β₁ (pendiente) de la recta y = β₀ + β₁·x usando las fórmulas de mínimos cuadrados, implementadas con funciones de agregación estándar de SQL: SUM(), AVG(), COUNT(). Con estos coeficientes se proyecta el monto esperado para los próximos 6 meses y se calcula el R² como medida de bondad del ajuste.

SalesOrderHeader Regresión Lineal Mínimos Cuadrados Forecasting R²

T-SQL 
-- ============================================================
-- EJEMPLO 10: Proyección de ventas con Regresión Lineal en SQL
-- ============================================================

WITH VentasMes AS (
    SELECT
        ROW_NUMBER() OVER (ORDER BY YEAR(OrderDate), MONTH(OrderDate)) AS X,
        FORMAT(OrderDate, 'yyyy-MM')   AS Periodo,
        SUM(TotalDue)                  AS Y
    FROM Sales.SalesOrderHeader
    WHERE Status = 5
    GROUP BY YEAR(OrderDate), MONTH(OrderDate), FORMAT(OrderDate, 'yyyy-MM')
),
Stats AS (
    SELECT
        COUNT(*)                    AS N,
        AVG(CAST(X AS FLOAT))      AS X_bar,
        AVG(Y)                      AS Y_bar,
        SUM((CAST(X AS FLOAT) - AVG(CAST(X AS FLOAT))) * (Y - AVG(Y)))
            AS SXY,
        SUM(POWER(CAST(X AS FLOAT) - AVG(CAST(X AS FLOAT)), 2))
            AS SXX,
        SUM(POWER(Y - AVG(Y), 2))  AS SYY,
        MAX(X)                      AS X_max
    FROM VentasMes
),
Coefs AS (
    SELECT
        N, X_bar, Y_bar, X_max,
        SXY / NULLIF(SXX, 0)                                   AS Beta1,
        Y_bar - (SXY / NULLIF(SXX, 0)) * X_bar               AS Beta0,
        POWER(SXY, 2) / NULLIF(SXX * SYY, 0)                  AS R_Cuadrado
    FROM Stats
),
Historial AS (
    SELECT
        v.X, v.Periodo,
        v.Y                                        AS VentaReal,
        c.Beta0 + c.Beta1 * v.X                  AS VentaEstimada,
        'Histórico'                                AS Tipo,
        c.R_Cuadrado
    FROM VentasMes v CROSS JOIN Coefs c
    UNION ALL
    -- Proyección de los próximos 6 meses
    SELECT
        c.X_max + n.num                                       AS X,
        'Proyección M+' + CAST(n.num AS VARCHAR)             AS Periodo,
        NULL                                                   AS VentaReal,
        c.Beta0 + c.Beta1 * (c.X_max + n.num)               AS VentaEstimada,
        'Proyección'                                           AS Tipo,
        c.R_Cuadrado
    FROM Coefs c
    CROSS JOIN (
        VALUES (1),(2),(3),(4),(5),(6)
    ) n(num)
)
SELECT
    X            AS PeriodoNum,
    Periodo,
    Tipo,
    FORMAT(VentaReal,      'C0', 'en-US') AS VentaReal,
    FORMAT(VentaEstimada,  'C0', 'en-US') AS VentaEstimada,
    FORMAT(R_Cuadrado * 100, 'N1') + '%'     AS R2_Ajuste
FROM Historial
ORDER BY X;
